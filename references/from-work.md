# 从现有工作流 / 工作记忆提炼 Skill

目标：把「已经重复发生过的工作」变成可复用的 skill，而不是凭想象写一个。

## 1. 来源清单（先列后读）

优先顺序：

1. 当前对话 / 最近会话：用户的原话、纠正、最终验收标准。
2. 工作记忆：`FACT.md`（长期事实）、`JOURNAL.jsonl`（事件流水）。
3. 项目文档：`AGENTS.md`、`README.md`、`docs/`、交接文档。
4. 可执行资产：`scripts/`、`Makefile`、`package.json` 的 scripts、PowerShell 历史。
5. 版本历史：`git log --oneline`、最近 diff。
6. 产物：截图、报告、交付包目录结构。

用 `scripts/scan_work_sources.py <目录>` 先拿清单（路径 / 类型 / 大小 / 修改时间），再用 `scripts/memory_digest.py <目录>` 看记忆摘要；只读候选文件，不要把整个目录塞进上下文。

## 2. 判断值不值得

满足任意两条再做：

- 同一组步骤重复 ≥3 次。
- 每次都要查同一份资料 / 口径。
- 输出格式固定，返工主要来自格式。
- 有明确验收标准，能判断对错。
- 换个人 / 换个会话也能按步骤复现。

反例：一次性排障、只发生一次的配置、依赖当前临时状态的操作。

## 3. 提取什么

| 从工作里找 | 放进 skill 的哪里 |
|---|---|
| 固定步骤 / 顺序 | SKILL.md 正文「流程」 |
| 判断条件 / 例外 | 正文「规则」或 `references/` |
| 长资料 / 查表 | `references/` |
| 重复执行的命令 / 校验 | `scripts/` |
| 输出模板 | `assets/` |
| 用户原话 / 触发场景 | `description` |
| 一次性的路径、账号、项目状态 | 不进 skill（留在记忆 / 文档） |

## 4. 写 description：用用户原话

- 收集 5–10 条用户当时真实说过的句子。
- 把高频名词、动词、口语说法塞进 description。
- 不要写「本技能用于……」；写「当用户说……时使用」。
- 用 `scripts/trigger_lint.py` 做词面冒烟，找漏掉的关键词。

## 5. 脱敏与边界

- 删除：API key、token、密码、内网地址、真实姓名、客户数据。
- 泛化：绝对路径改成「项目根目录」或环境变量；本机专用路径放 `compatibility` 或安装说明。
- 标注：依赖的外部系统、需要的权限、失败时的退路。

## 6. 验收：回放 3 个历史任务

选 3 个真实发生过、结果已知的任务：

1. 只给 skill + 任务描述，不看原始过程，能否复现？
2. 输出是否达到当时的验收标准？
3. 哪一步依赖了 skill 里没写的隐含前提？补进去或删掉该步。

3 个里至少 2 个完全复现，才算可用；否则回到第 3 步重写。

## 7. 最小化

- 先删后加：删掉不改变行为的句子。
- 一条规则只写一次；正文、reference、description 不重复。
- 能脚本算的，不写成「请模型计算」。
- 目标：正文 ≤200 行；超过就拆 `references/`。

## 8. 常见失败

- 把「项目事实」当「流程」写进 skill → 换项目就错。
- 把一次性操作固化成 skill → 维护成本大于收益。
- description 用自己的书面语，不用用户原话 → 不触发。
- 把整份 `JOURNAL.jsonl` 抄进 `references/` → token 爆炸且很快过期。
- 没有回放验收 → 看起来完整，实际跑不通。
